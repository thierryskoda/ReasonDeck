# ADR-002: Claude Desktop adapter

- Status: Accepted and runtime-enabled. Chat, Cowork, and Code passed signed live switching on Claude Desktop 1.40609.0 and Code on 1.46388.4. Claude Desktop 6.6395.0 replaced Code's separate model and effort controls with the combined picker; the adapter was rebuilt for that layout from a live Accessibility read, and passed unsigned live switching on 6.28899.2 through the opt-in live test; a signed Release live check is still owed before either version is listed as certified
- Scope: Claude Desktop Chat, Cowork, and Code model-and-effort selection

## Context

One physical shortcut should carry independent ChatGPT and Claude Desktop assignments. Claude Desktop exposes a combined model-and-effort picker in the Chat and Cowork composer, while paid accounts also expose separate Code composer controls. Merely checking the bundle identifier is insufficient. Terminal-based Claude Code is outside this decision because safely identifying the active prompt and session across terminals would require a separate integration contract.

Until Claude Desktop 6, paid Code exposed an exact model popup and a named effort slider instead. Claude Desktop 6.6395.0 gives Code the combined picker too, so one adapter path now serves every surface. The older Command-Shift-I and Command-Shift-E path stopped opening those controls in 1.40609.0.

## Decision

1. Store one shortcut chord with optional, independently typed ChatGPT and Claude Desktop assignments. Keep the persisted `claudeCode` field for configuration compatibility. At least one assignment must remain enabled.
2. Migrate version-1 configuration once into version 2 as ChatGPT-only. If version-2 data exists but is invalid, fail closed and never fall back to version 1.
3. Consume a matching event only when the frontmost application's enabled assignment matches. Capture the target and process at key-down without blocking the event-tap callback, then immediately require that process to remain frontmost and capture its focused-window identity before dispatch.
4. For Claude, require the captured Claude Desktop process and focused window to remain frontmost before every phase. Recognize one surface: one exact prompt field with one structurally related combined model-and-effort popup titled `Model: <model> <effort>`. The prompt label proves which tab it is and the two are mutually exclusive: `Write your prompt to Claude` for Chat/Cowork, and the generic `Prompt` only while the Code radio is selected. Accept Code's selected radio only through role-specific persistent state, including numeric value `1`; never infer it from appearance.
5. On every surface, open the exact combined popup and require an owned root menu, proven by the exact composer title, containing at least two closed-set models plus the exact `More models` row. The current model need not have a root row, because a model chosen from `More models` has none. Refresh the owned menu after its bounded settle period. If the requested exact model is present in that verified root menu, select its exact row there. Only when it is absent, focus `More models` through its exact verified geometry and send native Right Arrow to perform that focused row's submenu transition. Require the owned nested menu to contain at least two closed-set alternative models, then select one exact model-row geometry. If the owned menus remain open because Chromium used that first click only to focus a non-default row, wait the same bounded 500-millisecond responder-settle period, then reacquire the same verified menu and exact row before one activation click. Open the nested effort menu through its exact verified trigger geometry. Paid Claude's advertised `AXPress` actions can focus or close these rows without performing the intended transition, so every geometry and key action retains owned-menu and final-state verification.
6. Prefer direct Accessibility actions. Chromium can report successful `AXPress` and `AXShowMenu` actions while leaving the exact Chat/Cowork composer popup closed; only after both actions fail observable menu verification may ReasonDeck reacquire that same exact popup and click its current frame. A frame-derived HID click is otherwise permitted only for an exact row inside the popup's verified owned menu. The `More models` trigger and its exact nested model row omit a standalone preparatory hover because that hover rebuilds the Chromium row before mouse-down; they still derive mouse-down from the current verified row frame. Mouse events carry empty flags instead of inheriting the triggering shortcut's modifiers, and do not carry ReasonDeck's synthetic-key sentinel because the event tap subscribes only to keyboard events and Chromium refuses marked or shortcut-modified mouse-down activation. Revalidate the captured process/window immediately before delivery, constrain click points to current geometry, and restore the pointer afterward.
7. Identify an opened picker by its exact closed-set title on a container whose role is `AXMenu` (Claude Desktop 1.x) or `AXGroup` (6.6395.0), never by role alone. The root container carries the closed composer title, the nested ones `Effort <label>` and `More models`, and rows are matched only inside the container that owns them.
8. Select only exact labels from closed source sets. Do not use list position, substring guessing, fixed screen coordinates, terminal commands, or settings-file edits. Verify through the combined composer title; report failure even when an input appeared to work.
9. Keep terminal Claude Code integrations out of scope until a host-specific integration can prove the focused Claude prompt without reading or modifying conversation content. Cursor Agent/Chat model switching is covered separately in [ADR-003](ADR-003-cursor-model-picker.md).
10. Initialize Claude's web Accessibility bridge outside shortcut transactions when ReasonDeck detects an already-running Claude process, when Claude launches, and after permissions become available. Track that lifecycle bootstrap by process identifier so a relaunched Claude is initialized once without collecting content. During a shortcut, inspect the already-published composer first and retain missing-surface preparation only as a fail-closed fallback — but never latch that fallback once per process. Chromium can drop and rebuild the web tree many times within one process lifetime, so re-assert preparation at most once per 30-second cooldown per process, and re-wait for the exact captured window after every attempt. Preparation can temporarily unpublish or replace Chromium's focused native window, so never reinterpret or rebind the captured shortcut target.

## Consequences

- The same shortcut can safely select different profiles depending on which supported app is frontmost.
- Claude UI or Accessibility changes disable the adapter instead of selecting by position. The paid Chat/Cowork layout's verified root rows and conditional exact `More models` transition are part of that closed contract.
- A signed Release build passed live switching in Claude Desktop 1.40609.0 on a paid account. Chat passed Sonnet 5 Medium to High plus an already-applied High run; Cowork passed High to Medium; Code passed Opus 5/Low to Sonnet 5/Medium and then Medium to High.
- Signed 0.2.5 candidates exposed that manual Accessibility preparation can replace Claude's native window even when it is requested only after missing-surface discovery, so those in-transaction attempts correctly failed closed. With lifecycle bootstrap in place, ReasonDeck started before a cold Claude Desktop 1.46388.4 process, logged preparation for that process before any shortcut, and the first Code shortcut switched Sonnet 5/High to Opus 5/High in 0.792 seconds. Earlier bidirectional checks also passed Opus 5/High back to Sonnet 5/High.
- On 2026-09-14, one Claude Desktop 1.52386.3 process (running since 2026-09-11) published an empty web tree — zero inputs, popups, models, and efforts on both surfaces — for a shortcut whose once-per-process preparation had already been spent. Every later press polled the empty tree for the full deadline and failed closed with `claude_code_surface_not_found`; the same process and the same ReasonDeck binary switched normally 38 minutes later once Claude republished on its own. The unchanged process identifier ruled out a version-drift explanation. Preparation is therefore cooldown-bounded rather than latched, and each attempt is logged so a skipped or spent recovery is visible.
- Claude Desktop 1.52386.3 labels its top tier `Fable 5.1`. A read-only Accessibility probe of the Code composer returned the exact closed popup title `Model: Fable 5.1`. While that was the current model, no assignment could switch at all, because surface recognition requires the current model to parse from the closed set. `Fable 5.1` is its own exact model. `Fable 5` remains allowlisted until live evidence shows Claude no longer offers it; retire it by deleting the case and letting the decoder drop stale assignments. The Chat picker-row forms for `Fable 5.1` mirror the observed `Fable 5` forms and are extrapolated, not live-read; re-read the opened Chat menu before relying on Chat-surface `Fable 5.1` selection.
- Claude renames these controls between builds without changing their structure. Code's closed model popup was the bare model name in 1.40609.0 and `Model: <name>` in 1.46388.2–1.46388.4; the opened menu root was also observed as `Model: <name>` in 1.46388.3–1.46388.4, while the effort popup kept the `Effort: <label>` form throughout. Discovery and opened-menu ownership therefore share the same two exact allowlisted model-title forms. This remains independent of picker order and does not permit substring matching. When the prompt is found but no popup title parses, the adapter fails closed and logs `surface_missing phase=relationship` with `popups=0`, which points at a renamed control or a model outside the closed set. Re-read the live popup and menu-root labels before widening any matcher.
- Code's composer popups advertise `AXShowMenu` and `AXPress`, but on Claude Desktop 1.46388.2 `AXShowMenu` returns success while opening Chromium's generic text context menu (`Copy`, `Select All`) instead of the model or effort picker. Observed worse: an `AXShowMenu`-then-cancel cycle against the effort popup silently decremented the live effort one step per attempt. Those 1.x controls are gone, but the combined popup that replaced them is the same kind of Chromium control, so on the Code tab the adapter never sends `AXShowMenu`: it tries `AXPress`, then the verified composer-relative geometry click.
- Claude may append plan-usage copy to an effort row, such as `Max 2.5× or more usage` or `Max 3.5× or more usage`. ReasonDeck allowlists each observed full label and continues to reject unrecognized variants rather than matching a prefix.
- Current efforts are Low, Medium, High, Extra, and Max. Persisted Auto, None, or Ultracode assignments remain invalid for this live surface and are reported as unavailable instead of being coerced to a slider position.
- Claude choices can differ by plan or session. A missing exact item is reported as unavailable; ReasonDeck never substitutes a model or effort.

- Claude Desktop 6.6395.0 (2026-11-18) broke every Code shortcut with `claude_code_surface_not_found`, for three layout reasons found by one read-only Accessibility probe of the idle Code composer and its opened picker. First, Code dropped its separate model popup and effort slider for the same combined picker Chat uses: one `AXPopUpButton` titled `Model: Fable 5.2 Medium` beside the `Prompt` text area, a root list of model rows, an `Effort Medium` row opening Low / `Medium Recommended` / High / Extra / Max (plus a separate `Ultracode` row), and a `More models` row opening older models. Second, those opened containers are `AXGroup` elements with `AXMenuItem` rows, not `AXMenu`, and the nested ones sit at depth 39, beyond the previous 36-level scan. Third, the current model, `Fable 5.2`, was outside the closed set, which alone disables recognition. The separate-controls Code path was deleted rather than kept beside the new one: it could no longer be live-verified, and git history holds it.
- The same probe read an account-access badge: ` CVP` after the effort in the closed title (`Model: Sonnet 5.5 Medium CVP`) and ` CVP: Defense Access` on rows (`Opus 5.5 CVP: Defense Access`). Each is one exact allowlisted suffix on an exact closed-set name. Other accounts may show other badges; those fail closed until their exact text is added from a live read.
- On 6.6395.0 an `AXPress` on the composer popup, the `Effort <label>` row, and the `More models` row each opened the expected container without moving the pointer. That was not true of paid 1.x Chat rows (decision 5), so the geometry-click path stays; do not replace it with `AXPress` on the strength of one build.
- `Ultracode` is a separate row outside the five-level effort group and its closed-composer title has not been read, so a saved Ultracode assignment still reports unavailable. Chat and Cowork on 6.x were not probed; their 1.x label forms stay allowlisted beside the 6.x Code forms.
- The closed current-model requirement has now disabled every shortcut twice (`Fable 5.1`, then `Fable 5.2`). The model set therefore lists every name the 6.6395.0 picker offers, including the More models list, so switching away from any currently offered model works. A model Claude adds later still disables switching while it is selected.

- A fourth cause was independent of the layout and older than it: the window scan identified elements by `CFHash(AXUIElement)` and skipped any element whose hash it had seen. Distinct Chromium elements share hashes — 21 of 459 in one 6.28899.2 window — so the scan silently dropped whole subtrees. Whether the composer survived depended on which session was open: the same build recognized one Code session and reported `claude_code_surface_not_found` or a picker that "did not open" in two others, minutes apart. This also fits the unexplained 2026-09-14 empty-tree episode above, though that was not re-tested. The Antigravity adapter's source comment had already recorded the same collision; the Claude scan now uses the same remedy — position-based node IDs and `kAXChildren` only. Before blaming a Claude update for a missing surface, compare a plain depth-first count of the window against what the adapter's scan reaches.
- Live check on Claude Desktop 6.28899.2 (2026-11-20, unsigned `swift test` harness run with `REASONDECK_RUN_CLAUDE_LIVE_TEST=1`, Code tab): from Fable 5.2 / Low, effort to High, model to Sonnet 5 through `More models`, back to Fable 5.2 from that non-root model, effort back to Low; before and after composer titles matched. An earlier run in the same series also passed Haiku 5.5 as a root-row target. Chat and Cowork were not exercised.

## Supersession condition

Prefer an official local Claude Code model-and-effort API if Anthropic exposes one that preserves active-session scoping and verifiable final state. Revisit terminal support separately when a host-specific integration can prove the focused Claude prompt without reading or modifying conversation content.
